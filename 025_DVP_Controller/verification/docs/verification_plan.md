## 2. Scope

### 2.1 DUT and configurations

DUT boundary: m_dvp_controller with its APB4 CSR/FIFO_DATA endpoint, DMA request/acknowledge sideband, PCLK/data/VSYNC/HREF sensor inputs, both mode-specific FIFOs, and local reset/CDC logic.

| Config ID | Parameters / runtime mode | Coverage intent |
|---|---|---|
| CFG-DVP-PROFILE-24 | PARA_DVP_DATA_W = 8/10/12; PARA_DVP_SAMPLE_EDGE = rising/falling; PARA_DVP_VSYNC_ACTIVE = 0/1; PARA_DVP_HREF_ACTIVE = 0/1 | Elaborate and run all 24 compile-time profiles; exercise runtime PCLK_MODE=0 and 1 in each profile. |
| CFG-FIFO-BOUNDARY | PARA_FIFO_DEPTH = 2, 8 (default), 16 | Check both mode FIFO mappings and full/empty boundaries. |
| CFG-FIFO-INVALID | FIFO depth 1 and 3; DVP data width 9 | Negative elaboration checks must detect unsupported configurations. |
| CFG-TIMEOUT | Reset default 0xFFFF_FFFF; programmed values 0, 1 and 3 | Read back reset/programmed values; verify immediate, positive and data-arrival terminal behavior without attempting a 2^32-cycle wait. |

PCLK/APB clock ratios in simulation are synthetic asynchronous stress points, not product frequency limits. Gated-mode source events must satisfy the HDS constraint: VSYNC active for at least four APB cycles; successive selected pixel edges at least four APB cycles apart plus integration timing margin. Sweep the first pixel only after synchronized VSYNC frame state is established. Illegal timing is not used to claim data preservation.

### 2.2 Included requirements and scenarios

The approved source inventory is the 22 REQ rows, seven ERR rows, four PERF rows, and five APB4 protocol clause IDs in requirements.txt. The plan contains 51 obligation mappings across 17 test IDs. functional_matrix.md is generated by the skill tool and orders the widest combined scenarios first.

The plan checks capture edge/polarity/width, frame and HREF qualification, both data paths, toggle/held-data timing, ordering, overflow/W1C, APB protocol and FIFO_DATA semantics, timeout boundaries, decode errors, CSR reset/access, watermark/ACK/re-arm, safe mode changes, reset recovery, flush handshakes, frame count, parameter rejection, and synthetic rate behavior.

### 2.3 Exclusions and bounded claims

| Item | Reason | Verification elsewhere / limitation |
|---|---|---|
| Camera SCCB/I2C programming, XCLK, reset/PWDN and physical sensor electrical timing | Explicitly outside capture-only IP scope (REQ-SCOPE-001). | Sensor datasheet and board-level integration. |
| System DMA master, interconnect contention and SoC throughput | DMA is external; this block only raises dma_req and exposes samples via APB. | SoC integration verification. |
| Workload-specific FIFO depth and maximum service-stall sign-off (PERF-003) | Resolution, frame rate, peak PCLK, APB rate and maximum DMA stall are not supplied. | Keep as open integration sign-off; no product-performance claim. |
| Bundled-data analog setup/hold, metastability MTBF, CDC/RDC and SDC/STA | RTL simulation cannot prove physical timing or metastability behavior. | Separate CDC/RDC and STA review using integration constraints. |
| Sensor compatibility with every camera | HDS identifies no universal normative DVP profile; supported compile-time profiles are tested, but no sensor/mode is selected. | Camera datasheet and integration waveform review. |
| Baseline RTL comparison | User previously directed testing only modified RTL. | No baseline build or regression is in this campaign. |

### 2.4 Earlier evidence

The earlier Icarus testbench (27 directed checks) did not read captured pixels from FIFO_DATA, so it did not prove pixel values, ordering, zero extension or APB pop accounting, and its flush check peeked at internal signals. It and its logs were removed in the consolidation. The current oracle observes public interfaces only and independently compares sampled input pixels with APB output transactions.

## 5. Environment architecture

### 5.1 Block-level test environment

    DVP sequence/source model
      ├─ drives PCLK, D[W-1:0], VSYNC, HREF ───────────────► DUT sensor ports
      └─ input-event monitor ──► HDS-derived pixel/frame model ──► expected queue
                                                            │
    APB requester BFM ──► DUT APB4 CSR + FIFO_DATA ◄────────┘
          │                       │
          └─ passive APB monitor ◄┴── PRDATA/PREADY/PSLVERR
                     ├─ APB protocol checker
                     ├─ CSR predictor/checker
                     └─ FIFO scoreboard: expected queue vs returned APB words
    DMA ACK driver ◄── DMA request monitor on public o_dma_req/i_dma_ack
    All monitors ──► coverage counters and run result
    Formal harness ──► bounded APB/timeout/DMA/mode/flush properties

### 5.2 Components and oracle independence

| Component | Kind | Responsibility | Interface | Source | Independence / qualification |
|---|---|---|---|---|---|
| dv_dvp_source | Driver | Drive legal profile-specific sensor events and clock relationships | PCLK/data/VSYNC/HREF | New local SV component | HDS bounds; deterministic patterns and seeded constrained random. |

| dv_dvp_scoreboard | Scoreboard | Compare FIFO_DATA values, order, zero extension and one-pop accounting | APB completions plus expected queue | New local SV checker | Known answers and lost/duplicate/pop mutant qualification. |

### 6.2 Stimulus and constraints

- Pixel values: deterministic zero, maximum, walking-one/zero and tagged sequences; random values are bounded to [0, 2^PARA_DVP_DATA_W-1].
- PCLK/APB are independent in continuous mode; exercise synthetic phase/ratio points, not guaranteed frequency ratios.
- Gated mode: VSYNC active at least four APB cycles; no PCLK edge during active VSYNC or HREF-high invalid gaps; selected pixel edges are at least four APB cycles apart plus modeled digital margin. Sweep first legal pixel phase after frame state is established.
- FIFO depths: 2, 8 and 16 for legal cases, including default 8. Negative elaborations use depths 1/3 and data width 9.
- APB: legal setup/access; hold requester fields while PREADY=0; PSTRB=0 on reads; inspect PSLVERR/PRDATA only at completion. FIFO_DATA base 0x0100 and CSR map come from the copied approved workbook/JSON.
- Timeout: 0, 1 and 3 are cycle-checked; reset default is read back, not waited out for 2^32 cycles.
- DMA service stalls 0..32 APB cycles are synthetic only and do not close PERF-003.

## 8. Coverage and mutation targets

- Functional coverage: 100% planned reachable bins over width, edge, qualifier polarity, runtime mode, normal/boundary/error/reset/flush. Human review required for every exclusion.
- Checkers: every checker qualified with known answers and fault injection; mandatory properties non-vacuous and passing.
- Code coverage on DVP-owned RTL: proposed G0 targets >=90% line and branch, >=80% toggle, and 100% reachable FSM transitions. Common libraries reported separately with rationale.
- Mutation set: at least six critical classes in a copied/synthetic RTL variant: wrong sample edge, dropped toggle polarity, overwrite-oldest, early/double APB pop, timeout off-by-one/data-priority reversal, and premature/wrong-FIFO flush or unsafe mode change. Target 100% critical mutant kill and >=80% for the reviewed representative set. Never alter retained DUT baseline.
- Randomization is deterministic and bounded by HDS/APB constraints. Retain failing seeds and never weaken an oracle to pass.
